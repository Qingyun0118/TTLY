# 水下机器人上位机需求书

***2025.4.5***

## 功能说明

实现MCU与上位机之间的通信：

- MCU向上位机发送水下机器人的相关信息和参数如**姿态信息，深度信息，PID参数**，上位机上可自动（或手动）**更新显示相关信息参数**，并且上位机可修改某些参数并发送给MCU，MCU更新相关参数。

- 上位机能够控制水下机器人的运动（待定，如何实现？简单地通过改变推进器推力？**或者上位机只需发送方向信息如手柄摇杆方向信息，在下位机（MCU）处进行解析并处理实现水下机器人的运动控制**）

- MCU与上位机之间通过**串口进行通信**

## MCU到上位机通信协议设计

参考JY901串口通信协议：[JY-901模块数据解算方法-OpenEdv-开源电子网](http://www.openedv.com/forum.php?mod=viewthread&tid=79352&page=1&extra=#pid450195)

### 数据包格式

- **起始字节**：`0xAA`（1字节）
- **功能码**：标识数据类型（1字节）
- **数据字段**：具体参数值（多字节，按小端序拆分）
- **校验和**：`SUM = 0xAA + 功能码 + 数据字段所有字节`

### 功能码定义

| 数据类型          | 起始字节 | 功能码 | 数据字段内容                                                 | 校验和(高位和低位两个字节) | 数据帧尾 | 数据长度 |
| ----------------- | -------- | ------ | ------------------------------------------------------------ | -------------------------- | -------- | -------- |
| 是否连接成功      | `0xAA`   | `0x01` | `Conne_Check`（1字节，0x01-0x04为MCU当前模式MCU应答连接成功） | `SUM`                      | `0xDD`   | 6字节    |
| IMU数据和深度数据 | `0xAA`   | `0x02` | Acc_X, Acc_Y, Acc_Z；<br />Pitch_Angle, Roll_Angle, Yaw_Angle；<br />Pitch_Angle_Velocity, Roll_Angle_Velocity, Yaw_Angle_Velocity；<br />Sys_Depth(各四个字节) | `SUM`                      | `0xDD`   | 45字节   |
| `PitchPID`参数    | `0xAA`   | `0x03` | ``Pitch_Kp/Ki/Kd`（各4字节）                                 | `SUM`                      | `0xDD`   | 17字节   |
| `YawPID`参数      | `0xAA`   | `0x04` | `Yaw_Kp/Ki/Kd`（各4字节）                                    | `SUM`                      | `0xDD`   | 17字节   |
| `深度PID`参数     | `0xAA`   | `0x05` | `Depth_Kp/Ki/Kd`（各4字节）                                  | `SUM`                      | `0xDD`   | 17字节   |
| `RollPID`参数     | `0xAA`   | `0x06` | `Roll_Kp/Ki/Kd`（各4字节）                                   | `SUM`                      | `0xDD`   | 17字节   |
| `SidePID`参数     | `0xAA`   | `0x07` | `Side_Kp/Ki/Kd`（各4字节）                                   | `SUM`                      | `0xDD`   | 17字节   |

> 一个字节由8位二进制组成，一个字节可以表示两个十六进制数;
>
> 姿态角，角速度，加速度均可由jy901读取得到，MCU可以直接以16进制方式转发给上位机，所以这些数据只需要2字节；
>
> 但是**深度数据和PID参数**在MCU中是十进制，需要将其转换为16进制后才能发送，参考：[关于IEEE754单精度(32位)的计算步骤(超详细)_ieee754标准计算公式-CSDN博客](https://blog.csdn.net/yaowanliang/article/details/89102815)，将深度数据和PID参数（10进制小数）转换为16进制后需要**4字节**



#### 姿态角

| `0xAA` | `0x01` | `SPAnL` | `SPAnH` | `SRAnL` | `SRAnH` | `SYAnL` | `SYAnH` | `SUM` |
| ------ | ------ | ------- | ------- | ------- | ------- | ------- | ------- | ----- |

`SPAnL`: `Sys_Pitch_Angle`低字节

`SPAnH`: `Sys_Pitch_Angle`高字节

Sys_Pitch_Angle=((SPAnH<<8)|SPAnL)/32768*180 (°)

其他角度命名与计算同理

`SUM=0xAA+0x01+SPAnL+SPAnH+SRAnL+SRAnH+SYAnL+SYAnH+SDe0+SDe1+SDe2+SDe3`

#### 角速度

| `0xAA` | `0x02` | `SPPaL` | `SPPaH` | `SPPaH` | `SPPaH` | `SPPaH` | `SPPaH` | `SUM` |
| ------ | ------ | ------- | ------- | ------- | ------- | ------- | ------- | ----- |

`SPPaL`: `Sys_Pitch_Palstance`低字节

`SPPaH`: `Sys_Pitch_Palstance`高字节

Sys_Pitch_Palstance=((SPPaH<<8)|SPPaL)/32768*2000(°/s)

其他角速度命名与计算同理

`SUM=0xAA+0x02+SPPaL+SPPaH+SPPaH+SPPaH+SPPaH+SPPaH`

#### 加速度

| `0xAA` | `0x03` | `SXAcL` | `SXAcH` | `SYAcL` | `SYAcH` | `SZAcL` | `SZAcH` | `SUM` |
| ------ | ------ | ------- | ------- | ------- | ------- | ------- | ------- | ----- |

`SXAcL`: `Sys_X_Acc`低字节

`SXAcL`: `Sys_X_Acc`高字节

Sys_X_Acc=((SXAcH<<8)|SXAcH)/32768*16 *9.8(m/s^2)

其他加速度命名与计算同理

`SUM=0xAA+0x03+SXAcL+SXAcH+SYAcL+SYAcH+SZAcL+SZAcH`

#### 俯仰角/横摇角/偏航角/深度PID参数

| `0xAA` | `0x04/0x05/0x06/0x07` | `PPp0` | `PPp1` | `PPp2` | `PPp3` | `PPi0` | `PPi1` | `PPi2` | `PPi3` | `PPd0` | ...  |
| ------ | --------------------- | ------ | ------ | ------ | ------ | ------ | ------ | ------ | ------ | ------ | ---- |

`PPp0`: `Pitch_PID_Kp`第1字节

`PPp1`: `Pitch_PID_Kp`第2字节

`PPp2`:`Pitch_PID_Kp`第3字节

`PPp3`:`Pitch_PID_Kp`第4字节

其他PID参数命名同理

C语言转换代码：

```C
#include <stdio.h>
#include <stdint.h>
#include <string.h>
/*
计算机中所有数据（包括浮点数）最终以二进制形式存储在内存中，且不同类型的数据（如 float 和 uint8_t[4]）可以共享同一块
内存空间。浮点数遵循 IEEE 754 标准，单精度浮点数（float）占用 4 字节，其内存布局为：
1 位符号位 | 8 位指数位 | 23 位尾数位。
通过直接操作内存的字节内容，可以将浮点数的二进制表示与十六进制字节流互相转换，前提是 字节序对齐（即明确数据存储顺序）。
*/

/**
 * @brief 将4字节的十六进制数据（小端序）转换为浮点数
 * @param hexBytes 输入的4字节十六进制数组（小端序）
 * @return 转换后的浮点数
 */
float hexToFloat(const uint8_t hexBytes[4]) {
    union {
        float f;
        uint8_t bytes[4];
    } converter;

    // 小端序：低字节在前
    converter.bytes[0] = hexBytes[0];
    converter.bytes[1] = hexBytes[1];
    converter.bytes[2] = hexBytes[2];
    converter.bytes[3] = hexBytes[3];

    return converter.f;
}

/**
 * @brief 将浮点数转换为4字节的十六进制数据（小端序）
 * @param value 输入的浮点数
 * @param hexBytes 输出的4字节十六进制数组（小端序）
 */
void floatToHex(float value, uint8_t hexBytes[4]) {
    union {
        float f;
        uint8_t bytes[4];
    } converter;

    converter.f = value;

    // 按小端序存储字节
    hexBytes[0] = converter.bytes[0];
    hexBytes[1] = converter.bytes[1];
    hexBytes[2] = converter.bytes[2];
    hexBytes[3] = converter.bytes[3];
}

// 大端序版本
float hexToFloatBigEndian(const uint8_t hexBytes[4]) {
    union {
        float f;
        uint8_t bytes[4];
    } converter;

    // 大端序：高字节在前
    converter.bytes[0] = hexBytes[3];
    converter.bytes[1] = hexBytes[2];
    converter.bytes[2] = hexBytes[1];
    converter.bytes[3] = hexBytes[0];

    return converter.f;
}

void floatToHexBigEndian(float value, uint8_t hexBytes[4]) {
    union {
        float f;
        uint8_t bytes[4];
    } converter;

    converter.f = value;

    // 按大端序存储字节
    hexBytes[0] = converter.bytes[3];
    hexBytes[1] = converter.bytes[2];
    hexBytes[2] = converter.bytes[1];
    hexBytes[3] = converter.bytes[0];
}
// 示例测试
int main() {
    // 测试浮点数
    float original = 10.34;

    // 将浮点数转换为十六进制字节数组（小端序）
    uint8_t hexBytes[4];
    floatToHex(original, hexBytes);
    printf("十六进制字节（小端序）: %02X %02X %02X %02X\n", 
           hexBytes[0], hexBytes[1], hexBytes[2], hexBytes[3]);

    // 将十六进制字节数组转换回浮点数
    float converted = hexToFloat(hexBytes);
    printf("原始浮点数: %.2f\n", original);
    printf("转换后浮点数: %.2f\n", converted);

    return 0;
}
```

## 上位机到MCU通信协议设计

### 数据包格式

- **数据帧头**：`0xBB`（1字节）
- **功能码**：标识指令类型（1字节）
- **数据字段**：具体指令或参数（多字节）
- **数据帧尾**: `0xCC`（1字节）
- **校验和**：`SUM = 0xBB + 功能码 + 数据字段所有字节+0xCC`

### 功能码定义

| 指令类型           | 数据帧头 | 功能码 | 数据字段内容                               | 校验和(高位和低位两个字节) | 数据帧尾 | 数据长度 |
| ------------------ | -------- | ------ | ------------------------------------------ | -------------------------- | -------- | -------- |
| 是否连接成功       | `0xBB`   | `0x01` | `Conne_Check`（1字节，0x11上位机请求连接） | `SUM`                      | 0xCC     | 6字节    |
| 设置运行模式       | `0xBB`   | `0x02` | `Con_Mode`（1字节,`0x01-0x04`）            | `SUM`                      | 0xCC     | 6字节    |
| 获取`PitchPID`参数 | `0xBB`   | `0x03   |                                            | `SUM` |`|0xCC5字节||||
| 修改`PitchPID`参数 | `0xBB`   | `0x04` | `PitchKp/Ki/Kd`（各4字节）                 | `SUM`                      | 0xCC     | 17字节   |
| 获取`YawPID`参数   | `0xBB`   | `0x05 `                  |      | `SUM` | 0xCC     |6字节|
| 修改`YawPID`参数   | `0xBB`   | `0x06` | `YawKp/Ki/Kd`（各4字节）                   | `SUM`                      | 0xCC     | 17字节   |

#### 手柄

使用Xbox手柄，定义手柄A, B, X, Y键分别对应四种运行模式：待机模式(0x01)，测试模式(0x02)，AUV模式(0x03)，ROV模式(0x04)，即按下对应按键，上位机通过串口向机器人发送对应的数据帧，如按下A，上位机向机器人发送0xbb 0x02 0x01 0xcc，机器人进入待机模式。

定义手柄左摇杆作为机器人的方向控制，向机器人发送axisLeftX和axisLeftY的数值（需要将数值先转换为十六进制）控制机器人水平推进器实现水平方向的控制，通过R2(DepthAdd 0x02)和L2(DepthDown 0x03)控制机器人理想深度的增减来实现深度的控制
